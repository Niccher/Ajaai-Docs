## 1. Executive Summary & Core Prioritization

Given the 4-6 hour timebox constraint, the primary engineering objective was to ship a **rock-solid, testable, and cloud-deployable full stack product slice** that addresses real user workflows rather than an overextended, brittle prototype.

### What Was Prioritized:
1. **Deterministic Relational State & Authorization:** Building a multi-tenant permission engine where document access is strictly verified on every single request. Unshared documents return explicit `403 Forbidden` responses.
2. **Seamless Zero-Friction Persona Switching:** Reviewers should not waste 5 minutes registering two accounts and validating email links. A built-in navbar persona switcher (`Alice` ⇄ `Bob`) lets reviewers test cross-user collaboration in 5 seconds.
3. **Hybrid File Ingestion (PostgreSQL + MinIO S3):** Uploading `.md` or `.txt` preserves original raw assets in S3 object storage while parsing content directly into native HTML for rich editing.
4. **Zero-Build Frontend Architecture:** Using Bootstrap 5.3 + Quill.js via CDN eliminates Webpack/Vite bundle overhead, hydration mismatches, and build failures, ensuring instantaneous page rendering and single-container deployment.
5. **Production Cloud Portability (Docker Compose):** A 3-service container architecture (`web`, `db`, `minio`) that runs identically on local workstations and GCP Compute Engine VMs.

## 3. Data Model & Schema Design

The relational schema is normalized with foreign key constraints and cascade rules:

- **`User`**:
  - `id` (UUID PK): Unique identifier.
  - `email` (VARCHAR 255 UNIQUE): User identifier used by the persona switcher.
  - `name` (VARCHAR 255): Display name.
  
- **`Document`**:
  - `id` (UUID PK): Unique document identifier.
  - `title` (VARCHAR 255): Document title.
  - `content_html` (TEXT): Rich-text markup generated by Quill.
  - `content_text` (TEXT): Searchable plain text.
  - `owner_id` (UUID FK -> users.id, ON DELETE CASCADE): Document creator.
  - `minio_object_key` (VARCHAR 512, NULLABLE): S3 key for imported files.
  - `file_type` (VARCHAR 50): Format discriminator (`markdown`, `plaintext`, `native`).
  - `created_at`, `updated_at` (TIMESTAMP).

- **`DocumentShare`**:
  - `id` (UUID PK).
  - `document_id` (UUID FK -> documents.id, ON DELETE CASCADE).
  - `user_id` (UUID FK -> users.id, ON DELETE CASCADE).
  - `permission` (VARCHAR 20): `edit` (read/write) or `view` (read-only).
  - **Constraint:** `UNIQUE(document_id, user_id)` prevents duplicate permission records.

## 4. Deliberate Scope Cuts & Tradeoffs

| Feature | Decision | Engineering Justification |
| :--- | :--- | :--- |
| **Real-Time CRDT / WebSockets** | **Cut** | Building collaborative multi-cursor presence (e.g. Yjs / Automerge) requires 20+ hours of operational transformation logic and connection state management. Under 4-6 hours, it frequently causes ghost states and sync bugs. Debounced autosave (800ms) with explicit revision timestamps was chosen for rock-solid stability. |
| **OAuth2 / Magic Links** | **Cut** | Setting up Google OAuth or email SMTP verification requires third-party credentials and slows down evaluation. A persona toggle with seeded accounts (`Alice` and `Bob`) allows reviewers to evaluate sharing rules in 5 seconds without sign-up hurdles. |
| **Complex Binary Ingestion (.docx, .pdf)** | **Cut** | Parsing proprietary binary schemas requires heavyweight Java/Node runtimes or external conversion microservices. Supporting `.md` and `.txt` with S3 storage delivers immediate product value with zero external bloat. |

## 5. What I Would Build Next (With 2–4 Additional Hours)

If allocated additional time, I would implement:
1. **Document Version History & Rollback:** Snapshotting document revisions to a `document_versions` table on manual save or hourly intervals, allowing users to restore past drafts.
2. **Export to PDF / Markdown:** Using headless HTML-to-PDF rendering to let users download formatted documents.
3. **Comments & Mention System:** Threaded comments tied to specific text highlights with `@persona` notifications.
4. **Live Presence Badges:** Lightweight WebSockets broadcasting which collaborators currently have the document open (presence indicators without full CRDT complexity).
